Challenge. Set write_file to deny, reset, and — before stepping past the write — predict what the agent does next, how the run ends (stop_reason) and how many turns it takes. Then check.

Show answer
The gate refuses, but nothing crashes: _execute returns the text "Permission denied: 'write_file' is not allowed under policy 'ask'. Try a different approach or ask the user." and that text is appended as a tool_result message like any other observation. On its next call the model reads it, cannot edit the file, and replies without a tool call: it explains the one-line fix and asks the user to apply it or grant permission. A reply with no tool calls is the stop condition, so the run ends with stop_reason = "done" after 5 turns (transcript A) — "done" here means "the model stopped", not "the task succeeded": the tests are still failing, which is why Chapter 27's harness runs the tests itself rather than trusting the model's summary. Policy allow_read_only gives the same route; allow_all never asks.
