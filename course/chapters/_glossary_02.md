- **tokenizer** — the component that maps text to a list of integer ids and back; fixed before pretraining (Ch. 02)
- **byte-pair encoding (BPE)** — a compression algorithm that builds a subword vocabulary by repeatedly merging the most frequent adjacent pair of symbols (Ch. 02)
- **character-level tokens** — one token per character: tiny vocabulary, long sequences (Ch. 02)
- **word-level tokens** — one token per word: short sequences, unbounded vocabulary, unknown-word problem (Ch. 02)
- **subword tokens** — pieces between characters and words: common words are one token, rare words are split into common pieces (Ch. 02)
- **pre-tokenization** — splitting text with a regular expression into chunks that BPE merges never cross (words with a leading space, contractions, digit groups, punctuation) (Ch. 02)
- **digit chunking** — the GPT-4 pre-tokenizer rule that numbers are split into groups of at most three digits (Ch. 02)
- **merge** — one learned BPE rule: a pair of symbol ids and the new id that replaces them; the ordered merge list is the tokenizer (Ch. 02)
- **special token** — a reserved string such as `<|user|>` with its own id that is never split into pieces; used for chat structure and document boundaries (Ch. 02)
- **allowed_special** — the encode flag that decides whether special-token strings in the input are recognised (trusted template) or spelled out as text (untrusted input) (Ch. 02)
- **compression ratio** — bytes of text per token; higher means each token covers more text, and it depends on the corpus (Ch. 02)
- **vocabulary size trade-off** — a bigger vocabulary gives fewer tokens per text but a bigger V × d embedding matrix and rarer, less well-trained tokens (Ch. 02)
- **Byte Latent Transformer (BLT)** — a tokenizer-free model that reads bytes and groups them into variable-size patches based on next-byte predictability (Ch. 02)
