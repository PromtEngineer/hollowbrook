- **prefill** — the first phase of generation: one forward pass over the whole prompt that fills the KV cache; compute-bound (Ch. 07)
- **decode** — the second phase of generation: one forward pass per new token, reading the KV cache; memory-bound at small batch (Ch. 07)
- **softmax** — `p_i = exp(z_i/T) / Σ_j exp(z_j/T)`: turns logits into probabilities that sum to one (Ch. 07)
- **entropy** — `−Σ p_i log₂ p_i`, the average surprise of a distribution in bits; 0 when certain, `log₂ V` when uniform (Ch. 07)
- **greedy decoding** — always taking the highest-probability token (`temperature = 0`); deterministic and prone to loops (Ch. 07)
- **temperature** — the divisor applied to logits before the softmax; `<1` sharpens the distribution, `>1` flattens it (Ch. 07)
- **top-k** — sampling restricted to the `k` most probable tokens, renormalised (Ch. 07)
- **top-p** — nucleus sampling: keep the smallest set of tokens whose cumulative probability reaches `p` (Ch. 07)
- **min-p** — keep tokens whose probability is at least `min_p` times the top token's; the cut-off adapts to the model's confidence (Ch. 07)
- **repetition penalty** — dividing (positive) or multiplying (negative) the logits of tokens already in the sequence to discourage loops (Ch. 07)
- **KV cache** — per-layer storage of every past token's keys and values so each decode step processes only the new token; exact, size `2·L·kv_heads·head_dim·bytes·T` (Ch. 07)
- **arithmetic intensity** — FLOPs performed per byte moved from memory; for batch-`B` decode it is about `B` (Ch. 07)
- **ridge point** — a chip's peak FLOP/s divided by its memory bandwidth (~300 FLOP/byte on an H100); below it a workload is memory-bound, above it compute-bound (Ch. 07)
- **roofline** — the model that bounds a workload's speed by `min(peak compute, bandwidth × intensity)` (Ch. 07)
- **memory-bound** — limited by how fast bytes can be read from memory rather than by arithmetic; batch-1 decode is the canonical case (Ch. 07)
- **compute-bound** — limited by the chip's arithmetic rate; prefill and training are the canonical cases (Ch. 07)
- **static batching** — running a fixed group of requests together until the longest finishes (Ch. 07)
- **continuous batching** — scheduling at the granularity of one decode step so a finished sequence's slot is refilled immediately (Ch. 07)
- **paged attention** — allocating the KV cache in fixed-size blocks, like virtual memory, so variable-length sequences pack without fragmentation (Ch. 07)
- **speculative decoding** — a fast draft model proposes `k` tokens and the target verifies them in one pass, accepting the matching prefix; lossless (Ch. 07)
- **draft model** — the small model that proposes tokens in speculative decoding (Ch. 07)
- **target model** — the large model whose output distribution speculative decoding reproduces exactly (Ch. 07)
- **quantization** — storing weights (or activations) in fewer bits with per-group scale factors; fewer bytes means faster memory-bound decode (Ch. 07)
- **stop token** — a vocabulary entry (TinyLM: `<|end|>`) that a post-trained model emits to end its turn, halting the decode loop (Ch. 07)
- **prompt caching** — reusing the KV cache of a shared prompt prefix across requests so it is prefilled once (Ch. 07)
