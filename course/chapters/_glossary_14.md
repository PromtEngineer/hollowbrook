- **post-training** — every training stage after pretraining (SFT, preference learning, RLVR, distillation, safety), using far less data and aimed at changing behaviour rather than knowledge (Ch. 14)
- **chat template** — the fixed convention for writing a multi-turn conversation as one token sequence, using special tokens for roles and turn boundaries (Ch. 14)
- **base model** — a pretrained (and mid-trained) model that predicts the next token of any text and has never seen a conversation format (Ch. 14)
- **instruct model** — a base model that has been post-trained to answer inside a conversation format; also called a chat model (Ch. 14)
- **reasoning model** — a model additionally trained, usually with RL on verifiable rewards, to produce a long chain of intermediate steps and check its own work before answering (Ch. 14)
- **agentic model** — a model trained on multi-turn interactions with tools and environments so that it can act, observe a result, and act again (Ch. 14)
- **supervised fine-tuning (SFT)** — training a pretrained model on demonstrations in the chat template with next-token cross-entropy restricted to assistant tokens (Ch. 14)
- **reward model** — a model trained on preference pairs to output a scalar score for a (prompt, answer), used as the reward in RLHF (Ch. 14)
- **DPO** — direct preference optimization: a loss that trains the policy directly on (chosen, rejected) pairs without a separate reward model (Ch. 14)
- **reinforcement learning with verifiable rewards (RLVR)** — RL in which the reward comes from a program that checks the answer (a math checker, unit tests, exact match) rather than from a learned model (Ch. 14)
- **on-policy distillation** — distillation in which the student samples its own answers and a teacher model grades every token, giving a dense per-token signal (Ch. 14)
- **off-policy data** — training data produced by something other than the current model: humans, a teacher model, or an earlier checkpoint (Ch. 14)
- **on-policy data** — training data sampled from the model being trained at (or near) its current weights (Ch. 14)
- **special tokens** — vocabulary ids reserved for structure (roles, turn ends, padding) that are never produced by encoding ordinary text (Ch. 14)
- **loss mask** — a per-token 0/1 flag saying whether that token's prediction contributes to the training loss; in SFT only assistant tokens and their closing `<|end|>` are 1 (Ch. 14)
- **tool call** — an assistant turn in which the model emits a structured request (a JSON name and arguments) for the harness to execute, answered by a tool-result turn (Ch. 14)
- **alignment** — operationally, the property that a model's behaviour matches a written specification as measured by held-out evals; the "alignment tax" is the helpfulness lost (over-refusal) when safety data is over-weighted (Ch. 14)
- **cold start** — a small SFT stage on a few thousand long-reasoning examples, run before RL so that RL starts from a readable format (DeepSeek-R1's term) (Ch. 14)
- **strong-to-weak distillation** — training a smaller model from a larger one's outputs (off-policy) and then its token-level judgements (on-policy), as in the Qwen3 recipe (Ch. 14)
